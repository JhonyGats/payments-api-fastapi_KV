# AI_LOG: как я работал с ИИ-ассистентами над тестовым

## Инструменты

- **Ассистент в терминале (Hermes Agent, модель deepseek-v4-flash через API DeepSeek)**:
  постановка задачи по описанию из задания, генерация каркаса проекта,
  разбор ошибок по логам и правки.
- **Pytest и uvicorn** для самостоятельной проверки: прогоны запускал сам, тесты писали
  вместе с ассистентом, каждый я читал и проверял, что он проверяет результат,
  а не только код ответа. Сервер поднимал сам, все примеры запросов из README прогнал руками.

## Ключевые запросы

**1. Каркас и разделение ответственности.** Отдал ассистенту текст задания целиком и попросил
разложить проект по файлам: модели, схемы, бизнес-логика, роутеры. Отдельно попросил вынести
скидку, график рассрочки и переходы статусов в отдельный модуль `services.py`, чтобы их можно
было проверить тестами без обращения к API. Ассистент собрал структуру из пяти модулей,
я её принял и дальше правки шли по ней.

**2. Деньги в копейках.** Задал контекст прямо из задания: суммы целым числом в копейках,
никаких float, промокод KVITTO10 без учёта регистра, неизвестный код это 422.
Ассистент предложил целочисленное деление для скидки и `divmod` для графика рассрочки,
это совпало с тем, что требовалось: пример из задания 1 990 000 на 3 месяца
воспроизводится точно.

**3. Идемпотентность.** Спросил, как правильно отдавать 200 на повторный запрос
с тем же `Idempotency-Key`. Ассистент предложил сначала искать платёж по ключу, а гонку
двух одновременных запросов закрыть уникальным индексом на уровне базы, отдельный
`try/except` на нарушение уникальности. Я оставил именно этот вариант, потому что проверка
в коде от гонки не защищает.

## Где ассистент ошибся и как я это заметил

**1. Сломанная цена тарифа.** В списке тарифов ассистент вычислил цену младшего тарифа
выражением `990_00 * 100 // 100 * 100`, то есть 9 900 000 копеек вместо 990 000. Я читал
сгенерированный код и сравнил с заданием: 9 900 ₽ это 990 000 копеек. Заменил выражение
на константу с комментарием. Вывод для себя: числа в деньгах проверяю глазами, а не по названию
переменной.

**2. Падение тестов на Windows.** Тесты сначала заканчивались ошибкой: временный файл базы
не удалялся, потому что соединение движка держало файл открытым. Ассистент предложил
явно освободить движок и повторить удаление несколько раз. После правки прогон стал чистым.

**3. Устаревшая константа в ответе об ошибке.** Ответ 422 собирался через
`HTTP_422_UNPROCESSABLE_ENTITY`, и pytest выдал предупреждение об устаревшем имени
в установленной версии. Заменил на числовой код 422, заодно это не зависит от версии FastAPI.

**4. Расхождение сигнатуры с вызовом.** Когда переводил скидку с одиночной константы
на таблицу промокодов, ассистент поменял тело функции и место вызова, но оставил старую
сигнатуру. Pytest сказал прямо: `calc_discount() takes 1 positional argument but 2 were given`.
Поправил сигнатуру и сделал для себя правило: при правке функции согласуются четыре точки,
а именно сигнатура, тело, все места вызова и тесты.

**5. Падение на необязательном поле.** В том же месте потерялась проверка
`if body.promo_code is not None`, и функция упала на `None` с `AttributeError`.
Проверку вернул: аннотация `str | None` в схеме это прямое указание, что `None`
надо обработать отдельно.
